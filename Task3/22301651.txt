3. PARSER AND GRAMMAR
---------------------
I completed the grammar and semantic actions in 22301651.y. The parser supports

* Global and local variable declarations.
* Scalar variables and array declarations.
* Function definitions and parameter lists.
* Compound statements and nested blocks.
* Expression statements and assignment expressions.
* Arithmetic, relational, and logical expressions.
* Unary expressions and function calls.
* Control-flow statements such as if-else, for, and while.

The grammar writes the recognized productions and reconstructed source fragments

4. SYMBOL INFORMATION AND SYMBOL TABLE
--------------------------------------
I implemented the supporting symbol-table components in symbol_info.h,
scope_table.h, and symbol_table.h.

The symbol information structure stores the details required during semantic
analysis, including an identifier's name, token type, data type, symbol kind,
array size, and function parameter information.

Each scope table uses a hash table with separate chaining. The implementation
supports insertion, lookup, and removal of symbols in a scope. It rejects a
second declaration of the same identifier in the current scope and can print
the stored variables, arrays, and functions with their relevant details.

The main symbol table maintains a chain of nested scopes. A new scope is created
when the parser enters a compound statement, and that scope is removed when the
block ends. Identifier lookup begins in the current scope and continues through
the parent scopes, which provides the required lexical scoping behavior.

5. SEMANTIC ANALYSIS COMPLETED
------------------------------
I added semantic checks for the following cases:

* Multiple declarations of variables in the same scope.
* Duplicate parameter names in a function definition.
* Multiple declarations or definitions of a function.
* Variables declared with the invalid void type.
* Use of undeclared variables.
* Calls to undeclared functions.
* Use of an array without an index where a scalar value is required.
* Indexing a scalar variable as if it were an array.
* Array indices that are not of integer type.
* Incorrect numbers of arguments in function calls.
* Argument data types that do not match function parameter types.
* Type propagation through variables and expressions so that later checks can
  use the calculated expression type.

Error messages contain the line number and a description of the problem. The
total error count is printed at the end of each generated error file.
